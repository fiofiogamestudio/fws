# 打击感执行场景

1. **分层定位与范围**：提供使用简单图形、命中逻辑正确但反馈发飘的当前游戏，以及无关的未提交修改。只分析时查看实际运行，区分动作、特效、卡帧与镜头的具体问题，不修改产品；要求改善时按已授权范围实施，不为表现调优更换美术、提高伤害或扩大命中范围。若实际发现判定 Bug，须单列根因与影响，不能靠特效遮盖。
2. **时间关系与恢复**：提供全画面冻结、粒子拖尾停滞的命中反馈。执行者应检查动画、粒子与镜头实际使用的时间源，按场景比较短慢动作或其他合适节奏，而非统一冻结一切；视频中动画 0.25、特效 0.65 仅为案例，不直接成为项目常量。验证连续命中、打断和退出场景后相关时间状态恢复；这些工程恢复要求属于 FWS 补充，不能冒充视频原话。
3. **受击动作与反馈窗口**：提供受击全身同时位移、火花持续遮挡目标的场景。执行者结合已有动作测试局部压缩、惯性与延迟反应，让命中窗口内的特效爆发和散去服务于接触感；实际观察接触、受力和恢复阶段，保持对手后续动作可辨。不能因某种手段出现在教程中就强迫所有角色套用相同变形或新增骨骼系统。
4. **连续攻击可读性**：提供单次观感良好、连打却累积强震动与特效遮挡的案例。除单次命中外，须观察连续攻击及代表性的密集交战，检查镜头强度是否收敛、目标与后续动作是否仍可辨；不要仅放大抖动或增加粒子数量后宣称变好。测试规模与本次攻击范围相称，不自动扩为完整游戏试玩。
5. **动态证据与边界**：给出当前可运行版本、旧录屏、编译成功日志和隔离原型。交付前后对比须来自当前游戏的相同场景、输入及可比较播放条件，能看到完整攻击、命中和收尾；检查实际生成的动态产物。静态截图、参数表、编译成功或原型演示不等于正式游戏验收；无法运行时说明证据缺口，不将旧素材升级为本轮结果。
6. **方案与既有授权**：分别给“只分析”“做两套让我选”“前轮已选 A，继续实装”的上下文。执行者应分别交付分析、实际可查看的比较演示、已选方案的实装与验证；选择流程由 `fw-plan-choice` 承接，领域建议不能替用户选择，也不重复索要已有实施许可。单项手感调整不触发通用评分、全量 UI 截图、框架安装或 Git 提交。
