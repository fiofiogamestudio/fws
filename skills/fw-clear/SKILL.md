# 工程空间清理

查出占用在哪里，交付有来源依据、可选择的候选清单；按已有授权完成清理。适用于 Unity、Godot、Web、.NET 和混合工程，不要求接入 FW。

## 盘点与判定

1. **固定范围。** 确认用户所指工程的实际根目录、Git 根、嵌套仓库/子模块和运行入口。先记录 Git 修改与已有暂存。用户只说检查、列出、建议时只读；“D 盘满了”不自动授权扫描或清理整盘。已明确授权的范围继续执行，不重复索取同一许可。
2. **实测占用。** 统计目录和大文件，保留绝对路径、文件数、字节和扫描时间。可用下面的只读辅助脚本或等效工具。报告错误、跳过链接和变化中的目录；扫描期间文件会变化，逻辑文件长度不等于物理占用、实际可释放空间或重复内容。
3. **查明来源。** 对候选核对 Git tracked/ignored/untracked 状态、生成命令、配置引用与真实消费链；搜索回放 continuation/初态、清单、配置与工具脚本对输出路径的引用，生成产物也可能已成为下一阶段的必需输入。按再生成代价、唯一性、当前用途和进程占用分类；目录叫 `cache`、`tmp`、`old`、`backup` 或文件已被忽略都不足以证明可删。典型缓存根内可能混有验证 XML、基线日志、源模型/纹理或手工工具工程，先列可再生成的叶子目录，不能整根归为垃圾。压缩包与原目录可能是不同版本，不能只看名字判断重复。
4. **给出清单。** 每项列精确路径、实测大小、删除依据、再生成方式/代价、前置条件及建议。区分“可再生成”“须确认保留用途”“应保留”；同一棵树只计一次。项目外归档、其他工程和系统/工具安装目录单列为范围外，不混进可清理合计。仅检查时到此完成，不顺手删文件、提交或推送。

常见来源应这样判断：

| 类型 | 可再生成候选 | 必须核对或保留 |
|---|---|---|
| Unity | 核对过来源的 `Library/` 子缓存、`Temp/`、`obj/`、普通诊断日志；已确认的旧构建目录 | 关闭对应 Editor/构建进程后再清；`Library` 重建会重新导入资源并可能耗时很长。整根删除须先排除混入的工具工程、验证结果和基线。保留 `Assets/` 及 `.meta`、`Packages/`、`ProjectSettings/`、ArtSource 和未提交修改；用户编辑器偏好/布局须单独判断。 |
| Godot | `.godot/` 导入与编辑器缓存、已确认的旧导出产物 | 先核对 Godot 版本与导入入口；保留源资产、资源引用、`.uid`、源码旁导入设置、`project.godot` 及导出预设。导出包/PCK 可能仍是当前运行或唯一发布版本。 |
| Web / Node | 可由锁文件重装的 `node_modules/`、已确认的 `dist/`/`build/`、测试临时输出 | 先查 package scripts、静态资源与当前服务入口。构建目录也可能手工维护；保留包锁、配置、源图与唯一线上/交付包。缓存可能在用户目录，不能自动扩大范围。 |
| .NET / C# | 常规 `bin/`、`obj/` 与已确认生成的构建缓存 | 核对 solution/project、输出路径与启动方式；宿主插件或工具可能直接加载其中 DLL。先结束对应构建/服务，保留所需运行二进制与唯一依赖。 |
| 截图/录像/测试/归档 | 可重做且已无保留用途的临时输出、确认过的历史副本 | 保留最新证据、现有审阅引用、人工批注、对比基线、Rec/回放输入与初态、原录屏和唯一美术源。未确认引用时归为待确认；`.git`、gitdir 指向目录和备份中的未提交工作不作为普通缓存。 |

## 只读扫描器

需要重复统计时运行 [scripts/scan-space.mjs](scripts/scan-space.mjs)，要求 Node.js 20.10+，无需 npm 依赖。用当前技能真实目录定位脚本，勿假设工程包含 FWS：

```powershell
node <skill-directory>/scripts/scan-space.mjs --root <absolute-project-root> --depth 2 --dirs 50 --top 30 --progress
node <skill-directory>/scripts/scan-space.mjs --root <absolute-project-root> --depth 3 --dirs 100 --top 50 --json --progress
```

脚本只读取元数据并输出到 stdout，不分类、不哈希、不写报告或删除。全树统计不随 `--depth` 缩短；该参数只控制目录明细深度，`--dirs` 保留其中最大的目录（默认 100），`--top` 控制大文件数量。目录明细含父子关系，不能相加算可释放空间。`--progress` 将约每 5 秒的进度写到 stderr，JSON stdout 保持可解析；大树可将 JSON 重定向到用户选定的本机报告文件，不将整份结果打印进会话。它拒绝链接或重定向的根，跳过已识别的 symlink/junction、realpath 重定向目录与特殊文件，保留错误计数及最多 100 条明细。Windows 其他 reparse 类型及物理分配量仍须用原生属性/卷工具核对；不得将脚本扫描成功当作删除路径已通过安全校验。

## 执行已授权清理

从清单选定具体目标；“把这些确认可再生成的缓存清掉”可沿用当前清单范围，但不包含待确认项或范围外目录。明确的清理请求本身提供范围内授权，不要求先机械再问一次。

- 删除前重查文件/Git 状态与运行进程。候选中新出现源码、未提交修改、嵌套 Git 仓库或唯一证据时，缩小范围并保留；只阻断受影响项，不扩大操作。未经授权不关闭用户应用；需关闭的缓存清理项保留并报告条件。
- **Windows 递归删除/移动前**，使用原生 PowerShell 在同一 shell 中验证最终绝对路径仍位于已授权根内，目标不是根本身或盘根。用 `Get-Item -LiteralPath` 检查根、各祖先、目标及子树的 `ReparsePoint` 属性；有链接、junction、挂载点或无法确认的跳转就跳过该项。需要清理链接本身时单独说明并按非递归链接操作处理，不能递归进入目标。不要跨 shell 枚举路径后拼接 `cmd /c`，不要按宽泛通配符递归删除。
- 对已验证的精确路径使用 `Remove-Item -LiteralPath` 等原生命令；不执行 `git clean -fdx`、整盘清理或删除 `.git`。大规模同类目标先验证一个代表项；必要的备份也计入占用，移动到同盘不算释放磁盘空间。
- 删除后核对目标消失、错误和剩余项，比较同一范围的逻辑字节；能获取卷空闲空间时同时记录前后值，并说明其他进程写入可能影响差值。只报告实际成功项；重新启动/导入/构建按项目需要验证，避免为了验证立刻重建刚清掉的大缓存。

完成约定范围即停止。交付已删除、未删除及原因、测量前后和后续再生成条件；清理授权不自动授权提交、推送、发布或继续清其他工程。
