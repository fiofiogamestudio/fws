# 导出与运行核验

仅按实际引擎读取相关段落。不要把某个工程成功的压缩参数固定成跨项目默认值。

用于可复现构建的快照与最终运行包是两份清单。SDK/引擎选择文件（如 `global.json`）、导出配置与生成输入即使不进入运行包，也须保留在构建快照；不能复用运行包的排除规则把构建前提一起丢掉。

## Godot

- 从实际 export preset、主场景、autoload、`load`/`ResourceLoader` 路径和插件定位资源。配置选择“所有资源”时，测试/编辑器场景也可能把大量依赖拉进包；改为所选场景/资源前核验动态加载清单。
- 从 PCK 清单映射到原始资源与导入文件；比较源 PNG 大小不足以判断包内 `.ctex` 或 GPU 压缩的收益。保留 `.uid`、导入配置和资源映射，修改导入设置后重新导入再导出。
- 包内路径没有字面引用不表示资源无用；例如道具图标可由配置 ID 拼接路径。先追踪资源键到动态加载，再决定是否排除。
- 按当前版本的官方导出文档确认 Web 线程、扩展支持和加载器；自定义模板裁剪要保持项目实际所需模块，证明包体收益和运行功能。引擎版本与模板版本一致。

## Unity

- 读对应构建的 Build Report，区分引擎代码、场景、Resources、StreamingAssets、Addressables/AssetBundles 和重复依赖。不要根据项目 Assets 目录体积猜最终包。
- release/development、代码裁剪、纹理平台覆盖与音频设置均需保留配置基线。反射、序列化、动态类型及原生插件可能受裁剪影响；保留必要链接配置并跑实际功能。
- 按当前 Web 构建的 Compression Format、Decompression Fallback、构建文件名/后缀及加载器配置核对托管响应头；回退解压成功和浏览器原生流式加载分别记录。

## Web / 自定义引擎

- 读构建 manifest、chunk 图、资源加载器和实际网络日志；区分初始 chunk、懒加载、公共资源与重复依赖。先用生产构建而非开发服务器测量。
- 检查预压缩文件是否与原件同时被 ZIP 收入；如果上传两份是托管要求就保留并解释，否则按实际路由选取。不能盲删运行时仍引用的原件。
- 分包/远程资源减少主包不代表总下载减少。记录首次可玩与后续关卡下载，核验平台远程域名、缓存、资源校验和离线要求。

## HTTP 与质量证据

gzip/Brotli 常能显著减少未压缩文件的 HTTP 传输，但上传 ZIP 若已有 DEFLATE，再把文件预压缩通常不会获得同等的包体收益，甚至可能略增。两种口径均以重建后的实测字节数报告。

用实际托管路线冷缓存访问，记录响应状态、MIME、Content-Encoding、传输字节与解码后字节、启动完成时间；浏览器缓存命中、Service Worker 命中与未计入的晚到请求单独说明。计时固定设备/网络条件，网络优化结论不以一次偶然的热缓存加载为依据。

压缩后的引擎加载器能成功执行、WebAssembly 正确实例化、所有必需资源可取回，才算启动验证。检查代表性高对比/半透明素材、小字号/多语言文本、音乐循环与音效；字体需覆盖实际字重与字符集，不能只凭主菜单几行文字正常就裁掉其他字形。有损变更只在实际看/听证据支持时采用。
