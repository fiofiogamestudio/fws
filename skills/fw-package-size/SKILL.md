# 游戏包体审计与压缩

沿用游戏已有打包入口，不要求接入 FW。先回答“当前多大、按哪个口径、是否满足哪个平台的什么要求”，再根据用户授权完成优化。只问现状时不改打包配置；已经要求压缩时直接完成可回滚的实现与验证。

## 确认路线和基线

- 从发布脚本、导出预设、构建收据及实际上传物定位当前产物。区分 H5 网页、平台小游戏适配包、原生 APK/IPA 与源码压缩包；相同平台名称下的路线可能有不同限制。旧包标注构建时间/版本，不能当作当前源码的实测结果。
- 查目标平台**当前官方文档**，记录 URL、核验日期、路线、限制口径、单位，以及硬性限制还是体验建议。需登录或文档互相矛盾时明确未确认部分，不能凭记忆套用阈值或把其他小游戏平台的规则套过来。只有体积合规不能宣称 SDK、隐私、内容、设备兼容或上架审核全部合规。
- 保留改前产物、源版本/脏改状态、导出配置和 SHA-256。分别报告：上传 ZIP 字节数、展开后文件总量、最大单文件、首屏/进入可玩状态的实际网络传输；后者必须实测，不能拿 ZIP、磁盘文件或 Content-Length 相加代替。用字节作为比较依据，展示时注明 MB 或 MiB。
- 对目录或 ZIP 使用 [只读审计脚本](scripts/audit-package.mjs)，查看按体积排序的文件和扩展名汇总。容器文件（Godot PCK、Unity data/AssetBundle 等）还需对应引擎的内容清单/构建报告，不能把它作为无法解释的“大黑盒”。脚本不解包、不修改输入，也不验证 ZIP 内容 CRC 或真实网络请求。

## 按贡献优化

1. 先查最大的几项及其运行来源。优先排除已证实非运行必需的编辑器数据、重复交付物、调试符号、源映射、测试夹具和误收录素材；检查动态路径加载、DLC、字体回退与后续关卡，不能仅凭静态引用少就删除。
2. 优先采用相同内容的无损压缩、正确的 release 导出和资源去重。修改权威配置/生成入口，再重新构建；不只手工改一次产物。不能删除源资产、存档兼容、玩法或目标设备支持来换取数字下降。
3. 图片降分辨率/有损编码、字体子集、音频转码、引擎模块裁剪或分包需保留可回滚基线，按实际收益逐项尝试。验证文字全字符/语言回退、透明边、贴图滤波、循环音频、延迟加载与离线路径；代表画面和声音必须实际查看/听取。没有验收证据的候选不冒充正式采用。
4. gzip/Brotli 的网络节省与上传 ZIP 节省分别测量。改扩展名不等于正确压缩；确认平台上传/托管允许该格式，加载器映射、MIME、`Content-Encoding`、解压路径、缓存及跨源/线程相关响应头真实一致。不能只在自建开发服务器能跑就宣称平台可用。相应引擎关注点见 [导出与运行核验](references/engine-validation.md)。

## 重建、验收与交付

- 重跑正式打包入口，使用相同口径与基线比较。报告修改项、改前/改后字节数、节省百分比、大项与剩余下限；候选临时副本与最终交付包明确区分。
- 对实际交付目录/ZIP 解出的内容做冷缓存浏览器启动、进入可玩状态和一段核心流程，检查缺文件/404、控制台、字体/贴图/音频、后续资源及存读档。按目标补测移动端和平台预览；本地浏览器通过不能代替平台/真机验收。
- 审计脚本拒绝覆盖报告；输出放在包外，避免审计报告被下次构建收进去。若用其他工具解 ZIP，先拒绝绝对路径、`..`、盘符、链接和目标目录逃逸，再解到新隔离目录，避免直接覆盖现有输出。
- 达到目标、已无经验证的高收益低风险项时停止。若仍超限，列出按收益排序的后续方案及质量/兼容代价；不要无限尝试有损降质，也不要自动上传、发布或提交。

交付应让用户直接获得“当前包多大、已确认满足哪些体积规则、做了什么、还没验证什么”和最终包/报告路径。

## 审计命令

需要 Node.js 20.10+，无 npm 依赖。`--input` 接受目录或普通 ZIP；默认只在 stdout 输出 JSON。使用 `--output` 前先在包外创建父目录，脚本不会隐式创建目录。

```powershell
node <skill-path>/scripts/audit-package.mjs --input <build-directory> --output <outside-package>/before.json
node <skill-path>/scripts/audit-package.mjs --input <upload.zip> --top 20 --output <outside-package>/zip.json
node <skill-path>/scripts/audit-package.mjs --input <new-build-directory> --baseline <outside-package>/before.json --output <outside-package>/after.json
```

目录报告逐文件 SHA-256；ZIP 报告含归档 SHA-256、中央目录声明的压缩/展开大小、CRC32 和包装问题，并核对本地记录、负载范围与规范化路径碰撞。ZIP64、分卷包及无法可靠解析的 ZIP 会明确失败；报告不是解压完整性或平台合规证明。比较要求输入类型一致且基线汇总与条目自洽，`savedBytes` 为正表示减小。
