# 喵喵实例

这是保卫喵城 2026-10-08 的已验证导出方式，不是其他项目的固定布局。以下路径相对宿主根目录；先查当前代码与清单，不依赖旧批次的数量或日期目录。

## 来源与部件

- 角色入口：`src/config/game.json`、`src/config/units.json`；采用版本：`<host>/assets/miaocheng/editor2d/registry.json`。以当前配置及发布绑定为准，不从素材目录数量猜名单。
- 运行表现：`src/scripts/mode/game/feature/art/miaocheng_appearance_art_view.gd`。当时的解析顺序为鼠高清替换、显式外观、默认猫头眼嘴合成、默认眼睛覆盖、发布纹理。裸头图不等于最终脸。
- 猫源部件：`<host>/assets/miaocheng/appearance/` 的 catalog 与 default-cats，以及 `src/tools/fwd/sources/` 下采用的归一化 manifest。沿记录中的源路径/摘要追溯原画、归一化前部件和最终部件；不复制整个历史候选目录。
- 头、眼、嘴独立；毛色可能同时影响脸、身体和四肢。帽饰可分前后层，袖子、手持装备等沿实际 attachment 结构导出，不臆造更细拆分。当前完整角色由多张部件原画组成，不一定存在一张等价的完整原画。
- 同项目的鼠使用高清图集与网格 UV；基础接缝补面可能保留较低分辨率。逐格提取必须以实际映射确认边界，不能把任意图集一律假定为固定格子。

## 正式渲染与拆层

优先复用 `src/tools/fwd/character_preview_export_tool.gd` 的纹理解析逻辑，并检查当前实现。它处理共享纹理的语义所有者与独立表情，避免头/身体辅助网格被解释成另一种外观。

1. 初始化真实外观服务并应用发布 registry；用独立导出入口，不打开玩家存档。没有真实绘制能力的 headless/dummy 环境不能替代渲染截图。
2. 选定同一姿势与外观，先导出完整角色，再把该状态的有效纹理固定下来。固定前后整图应一致，然后逐 slot 隔离绘制；不要因隐藏其他 slot 而重新推断共享纹理的归属。
3. 用相同坐标、缩放和画布保存所有图层，保留实际从底到顶顺序。按整角色可见边界确定取景，特别检查长枪、帽子、弓弦和大炮。源部件另存原尺寸；渲染放大不增加原图细节。
4. 纹理像素去重时保留所有 `角色 → slot → attachment → 文件` 绑定；同一张图被不同网格引用，不代表可以删掉网格层。

本次采用 `idle@0`、1024×1024 透明 SubViewport，仅为交接姿势与尺寸的实例；动作验证需要另外选取动作和时刻。

## Alpha 与检查

本次 SubViewport 导出发现预乘 RGB，原始纹理则无需转换。先用标准 source-over 重组和黑/白底观察确认问题，不能仅凭 `RGB ≤ Alpha` 判定预乘，因为深色直通 PNG 也可能满足该条件。

确认后对**整图与渲染拆层**一起转换：`A > 0` 时 `RGB = clamp(round(RGB × 255 / A))`，`A = 0` 时 RGB 清零；Alpha 不变。记录已转换标记防止重复执行，并重建依赖这些图片的总览。不要处理已经是 straight-alpha 的源纹理。

再次按实际层序重组整图；分别检查 Alpha、可见区域和黑白底误差。低 Alpha 反除会放大 8 位舍入误差，应说明实际显示差异，不能照搬本次最大误差作为所有项目的验收阈值。最后核对来源摘要、透明边距、共用角色映射和文件完整性，再交付。
