# 运行端采集

只读识别项目与可用能力，再选择最短可靠路径。现有截图工具能满足需求时直接复用；游戏采集不要求 FWA/FWV 或新引擎。采集完成后的固定审阅与导出由 FWV 负责，不在宿主或技能里另写编辑器。

每张截图生成后，AI 实际打开并检查目标画面，再写入 `autoCheck.status` 与具体 `summary`。检查目标状态是否可见、是否仍处于过渡，以及文字、素材、遮挡和裁剪；只据已看到的证据区分安全、疑似和明确问题。图像尺寸、哈希或截图命令成功不能代替视觉检查，不能用备注关键词分类器补填结论。静态画面的检查结果与交互／玩法验证分别记录；已有截图也执行同样的逐图检查。

## Godot

- 从 `project.godot`、入口场景、Form／Widget、模态和页面分发定位清单；FW 项目从 `fw.toml` 识别脚本／测试路径与 gdscript／csharp 运行时，不假定目录或语言。
- 优先复用原生 GPU UI runner 与隔离存档。需要新适配时放临时目录或项目测试目录：实例化真实入口，使用既有状态导入和真实输入，等待绘制完成后从目标 Viewport 获取图像并保存 PNG。
- headless 模式可检查状态，但不能当作原生画面验收。已有脚本只输出截图路径不代表文件有效；核对 PNG、真实尺寸和界面内容。
- 设计坐标与窗口像素可能不同，输入按实际比例转换。记录窗口尺寸及逻辑视口；短屏可能改变布局，不能只缩放旧截图充数。
- 从战斗打开详情／菜单时，记录弹窗与暂停状态；用既有关闭路径回到游戏。为截屏冻结时间的夹具，应在证据中写明。

## Unity

- 识别启动场景、UI管理器、Canvas、Prefab及实际 UI 路由，不把编辑器中摆放的 Prefab 预览算成运行截图。
- 优先 Play Mode／独立 Player 的既有自动化和截图入口；设置真实 Game View／渲染目标尺寸，等待 Canvas 布局与一帧渲染完成再截取。
- 隔离 PlayerPrefs、存档及网络环境。不能隔离时先使用无需改进度的界面；不要为解锁页面写入玩家正式存档。
- 相机渲染结果可能不包含 Screen Space Overlay UI，核对最终 PNG 是否包含目标 Canvas。编辑器外框不算游戏分辨率。

## Web／HTML 游戏

- 使用环境提供且已阅读文档的浏览器工具；用已知本地入口或用户指定页面。浏览器截图适用于 DOM 和游戏 Canvas，无需依靠 AX 树解析 Canvas 内的文字。
- 记录真实视口和设备像素比；整页截图与可见视口截图分别标注。默认页面应否滚动由游戏设计决定，不能用整页长图掩盖默认视口溢出。
- 通过真实交互或工程已有 fixture API 切换状态；不直接重写 DOM/CSS造截图。存档涉及 localStorage／IndexedDB 时优先独立浏览器上下文或测试 origin，并记录来源。
- 对静态导出确认页面正在使用本轮构建；按浏览器工具约定刷新，避免把旧缓存画面称作当前实装。

## 其他引擎／已有图片

- 有原生截图或测试 API 时优先使用，否则用可用电脑控制工具。无法控制的系统、登录、设备或场景标 blocked；可给人工到达路径，不能臆测已截图。
- 用户只要求整理已有图片时直接建立图库，run.evidence 写明“整理既有截图”及来源。没有当前运行证据就不宣称“当前所有 UI 已覆盖”。生成器校验通过仅代表产物结构有效。

## 跨项目复用边界

通用部分是清单、证据、编号和图库；游戏特有的状态准备与入口留在宿主适配器中。不要把项目类名、固定端口、Boss数量、卡牌尺寸或既有测试套件复制进通用流程。只为必要状态增加夹具，截图任务不修改游戏数值或产品布局。
