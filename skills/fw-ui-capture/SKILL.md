# 游戏 UI 截图审阅

把用户指定范围的真实界面整理成可逐张反馈的图库。先建立覆盖清单，再截图；图片数量不能代替覆盖率。默认只采集和整理，不顺便重做 UI，也不为每个游戏重写审阅器。

## 确定覆盖范围

- 沿用当前工程、用户选定的版本和分辨率；未知时从启动入口、项目配置和现有运行窗口确认。`fw` 前缀不要求游戏使用 FWC，不安装框架或改运行时。
- 用户说“所有 UI”时，查入口场景、页面路由、Form/Panel/Prefab、模态分发、教程与测试夹具，同时从游戏入口实际遍历，互相补漏。先形成 `coverage` 清单，不只截当前可见页。
- 清单以“界面 + 可见状态”组织：如有／无存档，选择／禁用，空／满，战前／战中／暂停／结算，弹窗，长按／悬浮提示，分页／滚动末尾。仅在画面有实质差异时增加状态，避免穷举无意义组合。
- 共用模板按普通、最长文本、空内容、精英/Boss等真实差异取样；用户明确要求每张卡或每个角色时才逐项展开。默认使用项目默认比例；有适配要求或已知溢出时增加代表性短屏／窄屏。
- 单页或单张请求只覆盖指定范围，不扩展为全项目审计。保留不可达项及原因；已删除或不在范围的入口标为排除，不伪造截图补齐。
- 仅整理已有图片时，覆盖清单限于提供的图片与状态，标题及证据写明原始来源；不能从该批覆盖率推断全游戏覆盖。图片是否属于本图库的采用集合与是否来自最新构建是两件事：未被替换的既有图可供正常审阅，不因拍摄日期早而一律标历史。

## 采集真实画面

按 [运行端采集](references/capture-runtime.md) 选择项目现有测试入口、引擎截屏或可用浏览器／电脑控制工具。缺少某种工具时说明限制，继续能完成的部分。

1. 记录运行版本、时间、窗口／视口尺寸和证据来源，使用独立存档或浏览器上下文。避免覆盖玩家进度；需要状态夹具时优先复用已有测试设施。
2. 通过真实入口或可复现夹具到达目标，让实际游戏组件渲染。记录必要的操作路径及状态；夹具截图明确标明，不冒充完整玩家流程。
3. 等待资源和页面稳定；战斗、动画、提示等用可复现时刻，避免任意长睡眠。截取真实 PNG，不用 Imagegen、拼图、重绘或 DOM 模拟替代游戏截图。
4. 采集过程中由 AI 逐张查看真实 PNG，核对目标界面、资源、文字、遮挡、裁剪及意外滚动，并填写 `autoCheck: {status, summary}`：绿色 `safe` 表示在已查看范围内自认为无问题，黄色 `risk` 表示疑似问题，红色 `error` 表示明确问题。`summary` 必须写具体观察依据；不能按截图成功、日志成功或备注关键词批量推断安全。原始备注保留，除非用户要求修复，否则保持画面中的真实问题。
5. 保持同批输入稳定。若并行修改影响截图对应版本，仅重拍受影响项或拆分为独立批次；不把混合版本称为同一当前版本，也不为纯截图强制执行整套游戏回归。

“captured”只表示已获得可检查的画面；AI 的 `safe` 也只是有限视觉证据，不代表交互、玩法功能、手机实机或全流程验证通过。核对后才把清单项标为 captured；不能到达时标 blocked，并给出具体原因。未实际查看原图时不能宣称完成自动检查。

## 在固定审阅器中检查

按 [清单格式](references/manifest.md) 写 `capture.json`。稳定语义 `id` 用于识别状态，正整数 `number` 用于用户引用；按页面流程分配编号。每张图保存真实宽高、证据和简短标题。

默认将过程与夹具放入项目的临时目录，交付图库放入项目约定的产物目录。FW 工程通常为 `.local/ui-capture/<run>/` 与 `output/ui-capture-<run>/`；其他工程尊重已有约定。

使用 [薄入口](scripts/ui-capture.mjs) 调用 FWV 的 `ui` 工具（Node.js 20.10+）。采集游戏不要求接入 FW；审阅界面使用已有 FWV + FWE，验证与离线导出只需要 FWV。入口按 `--fw-root`、`FW_HOME`、技能真实 FWS 源目录的同级工作区顺序定位，验证 FWV 包和 CLI；显式路径错误时不回退，也不自动安装组件。

```text
node <skill-dir>/scripts/ui-capture.mjs validate --manifest <capture.json> --fw-root <FW-workspace>
node <skill-dir>/scripts/ui-capture.mjs serve --manifest <capture.json> --fw-root <FW-workspace> --fwe-path <FWE-directory> --port 0
```

打开服务返回的本地审阅地址。固定界面由 FWV 提供内容/API，FWE 提供编辑器壳；技能不携带编辑器或图库模板。缺少审阅依赖时报告具体缺项，保留已采集 PNG 和清单；有 FWV 时仍可离线导出。

- 人工结论与 AI 检查分开：通过 `accepted`、跳过／待审阅 `skipped`、不通过 `rejected`，缺省为 `skipped`，不能把 AI 的绿色直接当成人工通过。
- 界面不重复标题、编号和分类，不常驻操作说明或状态解释；自动检查直写具体结论，正常项可简短如“文字完整，未见遮挡”；保留真正的错误提示。
- 主审阅仅显示当前图，提供模块 `category`、自动检查、人工审阅三个筛选模块。检查筛选、编号定位、图片加载、保存及问题 JSON；历史数据保留追溯，不进入主审阅。
- “跳过”保持当前判定和备注，只循环前往后面下一个 `skipped` 项；最后一个未决项仍保留，全部已通过或不通过才停止。切换截图不能清空已写内容。
- 单张复制只输出当前截图 JSON；批量复制从所有当前图中选择 `review != accepted && (autoCheck 为 risk/error || review 为 rejected)`，不受界面筛选限制。字段及兼容规则见[清单格式](references/manifest.md)。
- 服务端备注保存在输入清单旁的 `review.json`，与该清单指纹绑定；修改清单前先导出备注并保留旧集合。离线 HTML 的浏览器本地备注不保证跨路径、端口或浏览器共享。
- 更新截图集时保留原 `id`、编号和原图字节；旧图标为 `historical`，新图使用新 `id` 和递增编号。只将真正替换的状态转历史，保留旧图库，构建新目录；当前覆盖引用新的截图。备注可先导出，避免丢失。

需要可离线交付的图库时，由同一 FWV 后端导出到**尚不存在**的目录：

```text
node <skill-dir>/scripts/ui-capture.mjs export --manifest <capture.json> --out <new-gallery-directory> --fw-root <FW-workspace>
```

导出保留原 PNG 字节，生成 `index.html`、`capture.json`、`coverage.json` 和审阅备注 `review.json`。旧 [build-gallery 命令](scripts/build-gallery.mjs) 仅兼容转发到此导出入口。交付前打开实际导出文件复核；不默认上传公开网站。

## 交付与停止

完成约定清单、核验图库后停止。简短给出图库入口、当前覆盖项数／未覆盖项和实测边界。部分可达也交付，明确列出 blocked／excluded；历史截图不计当前覆盖。截图请求本身不授权提交、推送或对外上传。
