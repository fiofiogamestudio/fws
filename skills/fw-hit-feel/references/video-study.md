# 学习摘要：从简单图形到清楚、舒适的打击感

来源：[一枚和菓子《用最简单图形做出打击感！真的能做到吗？》](https://www.bilibili.com/video/BV1taHC6dENS/)，发布于 2026-10-07，约 3 分 47 秒。学习日期：2026-10-30。

取材方式：读取官方未登录移动页面提供的完整 360P 视频，核对画内字幕、分层演示与前后对照。全片解码正常；按约两秒间隔查看覆盖全片的 113 个画面。以下为归纳，时间用于定位，非逐字稿；没有取得独立字幕文件，也未对声音做专项分析。原视频与抽帧仅留本地研究，不随技能分发。

## 视频的主线

作者用几何角色展示从朴素挥拳到多轮精修的过程：先补齐反馈手段，再调整这些手段之间的时间关系和视觉分量。评价重点由“冲击够不够明显”转向“玩家能否持续舒服地看懂战斗”。

| 约略位置 | 视频演示 | 可迁移的判断 |
|---|---|---|
| 00:27–00:41 | 简单挥拳加入圆环、线条和粒子，画面丰富，但仍缺少接触阻力 | 特效能标记命中，不能独自代替受力表现 |
| 00:42–00:56 | 在命中处加入短暂停顿，并展示受击抖动层 | 命中时序需要体现接触与阻力 |
| 00:57–01:10 | 增加屏幕震动，已有特效、卡帧与镜头反馈 | 镜头也是冲击感的一部分，但动作仍须成立 |
| 01:11–01:45 | 通过缩放、旋转、位移表达准备、发力、击退；蓄力时关注攻击者，命中时转向受击者 | 动作要有符合直觉的力量来源、传递和结果；镜头引导注意力 |
| 01:47–02:15 | 比较完全定住与角色低速续播；粒子和镜头继续运动 | 各层时间节奏可以不同，避免让受力停顿看起来像运行卡死 |

| 02:28–02:57 | 对比特效遮挡与收敛后的画面；强效果在受力窗口爆发并尽快消退 | 特效峰值及寿命应给对手下一步动作让出可见时间 |
| 02:58–03:15 | 将频繁攻击的强镜头运动收小 | 调整目标包括连续体验，不只是一拳的展示效果 |
| 03:16–03:35 | 回顾初版、要素齐全版与精修版 | 补齐技术要素只是起点，最终取舍来自想给玩家的体验 |

## 最值得保留的两个案例

**分开控制时间。** 对比画面标有角色动画 `0.25×`、特效照常运行；这说明低速角色动作可与持续的环境反馈一起表现压力，并不要求整个画面一起停住。画面另有 `慢放 ×¼` 的演示标注，那是给观众看细节的播放方式，不能与游戏内部动画速率混算。

**缩短遮挡窗口。** 精修对比标有特效时长从 `1×` 到 `0.65×`。可借鉴的是让主要爆发集中于接触/受力阶段，及时露出后续动作；不是所有特效都统一乘以 0.65，更不是为了让特效播完而锁住玩家。

这些数值只服务于作者的几何角色示例。视频没有给出适用于所有武器、帧率、引擎的卡帧毫秒数，也没有证明所有攻击都应低速续播、击退或推拉镜头。

## 转为 FWS 工作方法

下面是技能作者为工程实施补充的流程，而非视频的原话或已验证结论：

1. 从实际运行里找最影响接触感、可读性或舒适度的原因，保留可复现基线。
2. 用确认命中事件组织动作、卡帧、粒子与镜头时间线；逐层试验，保留改善，去掉遮挡与过量刺激。
3. 在既有表现层控制局部时间与变换，保护伤害、碰撞、输入规则和玩法随机；保证打断及并发后的状态恢复。
4. 用同条件原生运行对比验证正常速度与连续攻击；慢放只辅助定位，不替代最终体验。
5. 分别报告视觉结论、逻辑检查与已测性能。音效、设备适配等未检查范围不假报通过。

本技能吸收的是上述诊断和迭代方式。它不自动修改当前项目，也不把作者的几何美术风格、具体参数或技术实现变成所有游戏的规定。
