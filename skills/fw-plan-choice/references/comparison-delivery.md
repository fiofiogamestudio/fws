# 选择足够的演示证据

只读取本次相关的类型。复用项目现成的录制、截图、热切配置或浏览器预览入口，不把以下示例变成强制技术栈。

| 待选问题 | 合适的演示 | 必要的比较条件 |
|---|---|---|
| 静态布局、颜色、字号 | 同尺寸截图或可切换页面 | 相同文字长度、内容与状态；查看原图的裁剪与层级 |
| 动画、攻击路径、转场节奏 | 可重放原型或视频；可暂停、慢放时更易比较 | 相同角色、场景、视角、输入及播放速度，包含前后完整状态 |
| 交互、导航、手势 | 可操作原型或完整操作录像 | 同一个任务目标，包含入口、关键反馈、完成和取消/恢复 |
| 规则或技术架构 | 同输入下的行为例子、数据对照、小实验或流程图 | 指标定义、实验环境、成本与已验证边界一致；不必做视觉原型 |

## 简单比较入口

已有审阅页就增加本次对比；没有时，少量本地 HTML、独立图片/视频或内联可视化都可以。以可比较为目标，不固定布局或数量。

- 静态差异适合并排；长流程和动画可共用一个查看区域切换。显眼地显示基线/选项 ID 和名称，让用户能说“选 A”。
- 动画提供播放/重播和原速，条件允许再加暂停、慢放、统一时间轴。不能因额外控件做不到而阻止基础视频交付；没有验证过的按钮不要保留为假功能。
- 简短文案只写核心差异、适用条件和必要的限制，不把技术日志铺进面向用户的演示画面。
- 页面至少检查所引用产物存在、真实尺寸/时长正确且能加载。HTTP 成功只证明可获取；浏览器不可用时说明未验证网页交互，并直接交付已经检查过的媒体文件。
- 保留媒体的本地副本或项目产物目录，不把临时服务地址当成唯一持久成果。独立视频默认按需加载，避免多段视频抢占内存或同时播放。

## 精简交接记录

记录可以是产物旁的一小段 Markdown、JSON 或项目已有实验记录，无需新数据库。只保留后来恢复任务必需的信息：

- **问题与范围**：要解决什么、哪些行为保持不变，当前是规划/待选/已选落地。
- **基线**：所用源码/配置或版本，场景、输入与资源；没有可运行基线时如实说明。
- **选项表**：稳定 ID、名称、具体差异/参数、代价、演示路径和实际验证状态。
- **选择**：未选则明确待选；已选时记录用户的 ID 或组合要求，避免把推荐写成已采用。
- **落地结果**：最终代码/配置位置、新验证证据和未解决限制；区分原型与正式实现。

例如攻击移动对比可固定角色与目标，展示“快进快退”“跃起落击”“公共攻击位”之间的路径与时序差异；这只是示例。具体动作数量、站位、时间和引擎均从目标项目与用户反馈决定，不继承旧项目的数值。

## 修订与停止

用户说差异太小或指定局部调整时，围绕反馈迭代，保留旧版和选项身份；实质换方案时增加版本或新 ID。基线或资源改变后重拍受影响的对比，别把不同来源拼成同批当前证据。

待选阶段以“约定方案已能比较，入口已检查，限制已说明”为完成条件，然后等待选择。已选阶段以“对应方案已接入且相关验证完成”为完成条件；不继续自动生成更多方案。
