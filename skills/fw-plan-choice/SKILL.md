# 方案对比与选定落地

把尚未确定的设计决策变成用户能比较、能选择的具体成果，并保留选择到实装的对应关系。适用于游戏、界面、动画、交互及技术方案；不要求项目使用 FW，不自动安装框架或发布产物。

## 先识别当前阶段

- **规划**：用户只要分析或文字方案时，按请求给出取舍；不擅自制作产品原型。
- **演示待选**：用户要求“做几个演示给我选”时，方案说明与可查看的演示都属于交付。先完成可审阅成果，再请用户选择；只给计划、源码或参考图链接不算完成演示。
- **已选落地**：如“先用 A”“B 的布局加 A 的动效”，先从本轮或已有记录对应到具体方案，保留此前目标和约束，直接完成已授权的实装与验证。选择已明确时不重复询问是否开始；只对无法对应的选项或实质冲突补问。

用户已授权自主选择并实现时，给出取舍并继续，不另设强制选择关卡。用户明确保留选择权时，完成演示后停在选择阶段；推荐不等于用户已选择。选中方案通常授权所讨论范围内的实现，不自动授权提交、推送、部署或对外上传。

## 查清现状与比较对象

1. 读取项目规范、现有入口和相关代码/配置/素材，确认实际表现由谁控制。对“看起来不对”的现象先查证，不直接把用户猜测当根因。
2. 保留可复现的基线：当前行为、代表场景、输入/状态、视口与必要版本信息。已有未提交工作可以是基线；不要为了得到干净仓库而回退它。没有现成产品时明确“新建原型，无旧版基线”。
3. 提取本次真正待选的维度，例如运动路径与节奏、信息层级、操作步骤或技术成本。固定与决策无关的素材、数据、随机种子和测试条件，避免换了角色/内容/镜头后无法判断差异。
4. 只补问会改变方案或阻止演示的信息。可从上下文推断的普通实现细节自行决定，轻微未知可说明假设后继续。用户要单个动作或页面时不扩展全项目审计。

## 做有区别的备选方案

- 按决策复杂度提供少量可理解的备选，通常两到三个即可；数量遵从用户，不为凑数制造细微差异。沿用稳定的选项 ID（如 A/B/C）和短名称，本次已确认的现状单列为“基线”，历史版本另标历史参考；后续不要把同一个 ID 偷换成另一方案。
- 每项说明具体行为、与基线的差异、适用场景和主要代价。建议要有与用户目标相关的依据，不用无依据评分或把偏好包装成测量结论。
- 优先复用真实资源、组件与现有演示入口。原型放在可隔离的试验目录、配置开关、分支或工作树；选择前保留正式默认行为和原始资源。无需为几个方案造一套编辑器。
- 如果只改参数，记录参数即可；如果不同方案改变机制，明确其规则差异，不能只标成“视觉优化”。

## 演示与检查

根据 [演示交付细则](references/comparison-delivery.md) 选择足以支持本次决策的媒介。静态布局可用截图；时间、路径、节奏需要可播放或可重放的运动证据；操作流程需要实际交互或完整操作录像。技术方案使用可比较的接口例子、实验结果或图表，不强制做游戏画面。

- 演示默认复用同一基线和代表场景，明确显示方案 ID 与差异。动画保留完整的准备、执行、收尾，不能只截有利的一帧；需要比较时间时保持一致的帧率/播放速度。
- 实际运行或渲染每个待选方案，查看新产物。动画至少检查运动阶段和衔接，交互检查关键入口与恢复；结构测试、编译成功、捕获成功不代替这些检查。
- 打开实际交付入口，核对资源加载、切换/播放和可定位性。存在可用的项目审阅器时优先复用；已有截图整理可交给 `fw-ui-capture`，但本技能不触发全量 UI 截图。
- 运行工具不可用时，换成权限允许且能支撑判断的媒介；如用真实离线渲染视频替代失效的交互预览。标清“原型”“实际项目运行”“历史参考”“未验证”，不把模拟结果说成实机，也不绕过工具拒绝或安全限制。
- 编译/运行被无关改动阻断时，保留错误并隔离诊断。若使用替代环境或仅验证副本的临时调整，记录与正式源码的差异及证据边界；不能悄悄改正式行为使演示通过。仍无法获得所需证据时交付已有成果并说明缺项，不声称演示完成。

## 交付选择与承接实现

演示交付时给出可打开的比较入口、稳定选项 ID、各方案的核心取舍和简短建议。把相关的基线、方案参数、演示位置、验证边界保留在产物旁的简短记录中；不让用户从日志中自行拼出方案。用当前可用的文字或选择工具收取反馈即可，不要求另建投票系统。

收到选择后核对源文件是否仍对应演示版本；既有演示仅补验受漂移影响的部分，正式接入仍按本次改动验证。沿项目原架构接入所选方案，保留既有无关修改；组合选择要明确继承哪些元素。按改动验证正常流程、打断/取消/归位等相关边界，再从真实入口取得新的实现证据。原型录屏不能自动升级成正式版验收；未选中的试验不进入默认产品。

报告所选方案、实际改动、验证结果与仍存在的限制，给出新的可查看入口。用户仅要求提供候选方案时，停在可审阅的选择阶段；用户表达采用方案或已授权自主实现时，完成实现再结束。提交、推送或发布仅在已有明确授权内进行。
