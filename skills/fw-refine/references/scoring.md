# 可比较的评分

只在用户明确要分数、满分或持续多轮打磨时建立完整量表；分数是决策工具，不是客观精度承诺。

## 基线

- 固定范围、用途、版本和不可破坏的约束；选 4–8 个相关维度，定义权重、判分条件和证据门槛，权重合计 100。
- 每维 0–10 分：0 为缺失，6 为基本可用但有重要问题，8 为扎实且仍有改进，9 为成熟，10 为当前范围内无有意义改进。
- 原始分为加权平均，最终分为原始分与最低适用上限的较小者，最多保留一位小数。
- 改后沿用同一量表；目标或范围改变时另建基线，不直接比较新旧分数。

## 有证据才应用上限

| 条件 | 最高分 |
|---|---:|
| 核心成果未成立 | 5.9 |
| 存在严重正确性错误 | 6.9 |
| 关键流程不可达或存在数据/架构风险 | 7.9 |
| 核心效果没有真实或等效验证 | 8.4 |
| 缺少与改动风险相称的回归保障 | 8.9 |

上限必须与成果类型有关；不能因文档没有运行测试就自动扣分。未知通常降低可信度，直接涉及核心效果时才触发验证上限。

## 高分与可信度

- 9.0 以上：核心用途成立，没有已知重要问题。
- 9.5 以上：必要验证完整，没有已知高收益改进。
- 10：当前范围内没有有意义的改进；剩余只属范围外或主观偏好。
- 可信度高：关键结论有运行、集成、视觉或等效证据；中：主要结论已验证但有缺口；低：主要依赖静态或推断。

每次扣分说明证据，只有验证后的改善才加分；历史产物必须绑定版本，不能自动证明后来的修改。

## 最短报告

通常只用一行列出维度、权重与上限，再给总分、可信度和最重要证据；详细分项仅在用户要求或争议需要时展开。
复评报告变化与剩余问题，不反复复述量表；最后明确继续或停止及理由。
